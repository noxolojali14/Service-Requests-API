# Service Request Management API

A beginner-friendly service request manager built with Node.js and Express. Its REST API lets a client create, view, replace, partially update, and delete requests. A small browser interface at `/` uses the same API. Requests are stored in memory; this project does not use a database.

## Live Demo
https://service-requests-api.onrender.com


## Project Objectives

- Practise building a REST API with Express and JSON.
- Organise code into routes, controllers, data, and middleware.
- Validate input and return useful HTTP status codes.
- Test API behavior with Postman.

## Technologies

- Node.js and CommonJS JavaScript
- Express.js
- HTML, CSS, and browser JavaScript for the request page
- dotenv for environment variables
- npm for package management
- Postman for API testing

`server.js` configures Express, JSON parsing, static files, and middleware. `public/index.html`, `public/site.css`, and `public/app.js` make up the browser interface. The page calls the API on the same server. `requestRoutes.js` maps HTTP methods and URL patterns to controller functions. `requestController.js` validates input and performs CRUD operations. `requests.js` holds the in-memory array. The middleware files handle unknown URLs and errors consistently.

## Setup

### 1. Check Node.js and npm

In a terminal, run:

```bash
node --version
npm --version
```

Install a current Node.js LTS release if either command is unavailable. On Windows PowerShell, `npm.cmd` can be used if script execution policy prevents running `npm`.

### 2. Install dependencies

Open a terminal in this project directory and run:

```bash
npm install
```

This installs Express, which handles HTTP requests, and dotenv, which reads settings from `.env`.

### 3. Configure the port

The included `.env` sets `PORT=3000`. `.env` is ignored by Git so local configuration is not committed. `.env.example` documents the variable needed by another developer. Environment variables keep machine-specific configuration outside source code and make it easier to use different settings in development and deployment. Do not put passwords or API keys in a committed file.

### 4. Start the server

```bash
npm start
```

The server prints the port it is using. To use the complete application, open `http://localhost:3000/`; Express serves the page, stylesheet, and API. The API information response is at `http://localhost:3000/api`, and request endpoints remain under `/api/requests`. You can also open `public/index.html` with VS Code Live Server. Start Express in a separate terminal so the page can send API requests to port `3000`; local CORS access is limited to localhost origins for development. If an older stylesheet is cached, refresh with `Ctrl+F5`. Stop the Express server with `Ctrl+C`.

## Request Data

A service request has these fields:

| Field | Description |
| --- | --- |
| `id` | UUID generated by the server |
| `title` | Short problem description |
| `description` | Details about the issue |
| `requesterName` | Person who submitted the request |
| `priority` | `Low`, `Medium`, or `High`; defaults to `Medium` |
| `status` | `Open`, `In Progress`, or `Resolved`; defaults to `Open` |
| `createdAt` | ISO date/time generated by the server |

Example request body:

```json
{
  "title": "Wi-Fi keeps disconnecting",
  "description": "The connection drops every few minutes in the meeting room.",
  "requesterName": "Jordan Lee",
  "priority": "High"
}
```

Example created response (the generated ID and timestamp will differ):

```json
{
  "id": "b6f8f6b1-1234-4e10-a123-123456789abc",
  "title": "Wi-Fi keeps disconnecting",
  "description": "The connection drops every few minutes in the meeting room.",
  "requesterName": "Jordan Lee",
  "priority": "High",
  "status": "Open",
  "createdAt": "2026-10-16T12:00:00.000Z"
}
```

## API Endpoints

All endpoints return JSON. Send `Content-Type: application/json` when sending a JSON body. List and single-item GET responses return the request array and request object directly. Errors use `{ "error": "..." }`.

| Method | URL | Purpose | Success |
| --- | --- | --- | --- |
| GET | `/` | API information | `200 OK` |
| GET | `/api/requests` | List requests; returns `[]` when empty | `200 OK` |
| GET | `/api/requests/:id` | Get one request | `200 OK` |
| POST | `/api/requests` | Create a request | `201 Created` |
| PUT | `/api/requests/:id` | Replace editable request details | `200 OK` |
| PATCH | `/api/requests/:id` | Update only supplied editable fields | `200 OK` |
| DELETE | `/api/requests/:id` | Delete a request | `200 OK` |

POST and PUT require non-empty `title`, `description`, and `requesterName`. Priority and status are optional on those methods and default to `Medium` and `Open`. PATCH accepts one or more editable fields. Text fields must be non-empty strings when provided. Priority and status must match the allowed values. `id`, `createdAt`, and unknown fields cannot be changed. Missing IDs return 404; invalid bodies return 400.

## Postman Testing Guide

Start the server, create a Postman collection, and use `http://localhost:3000` as the base URL (replace `3000` if you configured another port). For JSON bodies, choose **Body > raw > JSON**; Postman will set `Content-Type: application/json`. Use the `id` returned by the create request for the existing-request tests below.

### 1. API information

- Method and URL: `GET http://localhost:3000/`
- Headers/body: none
- Expected status: `200 OK`
- Expected body:

```json
{
  "message": "Service Request Management API",
  "requestsUrl": "/api/requests"
}
```

### 2. List all requests

- Method and URL: `GET http://localhost:3000/api/requests`
- Headers/body: none
- Expected status: `200 OK`
- Expected body: `[]` before creating anything; otherwise an array of request objects.

### 3. Create a valid request

- Method and URL: `POST http://localhost:3000/api/requests`
- Header: `Content-Type: application/json`
- Body:

```json
{
  "title": "Install spreadsheet software",
  "description": "Please install the approved spreadsheet application on my laptop.",
  "requesterName": "Morgan Patel",
  "priority": "Medium"
}
```

- Expected status: `201 Created`
- Expected body: the new request object, including a generated UUID, current `createdAt`, and default `status` of `Open`.

### 4. Reject missing required fields

- Method and URL: `POST http://localhost:3000/api/requests`
- Header: `Content-Type: application/json`
- Body: `{ "title": "Computer will not start" }`
- Expected status: `400 Bad Request`
- Expected body: `{ "error": "'description' is required." }`

### 5. Reject invalid priority and status

- Method and URL: `POST http://localhost:3000/api/requests`
- Header: `Content-Type: application/json`
- Body:

```json
{
  "title": "Computer issue",
  "description": "The computer will not start.",
  "requesterName": "Alex Kim",
  "priority": "Urgent",
  "status": "Waiting"
}
```

- Expected status: `400 Bad Request`
- Expected body: `{ "error": "'priority' must be Low, Medium, or High." }`
- To check status validation, change priority to `High` and send again. Expected: `400 Bad Request` with `{ "error": "'status' must be Open, In Progress, or Resolved." }`.

### 6. Get one existing request

- Method and URL: `GET http://localhost:3000/api/requests/{id}`
- Headers/body: none
- Expected status: `200 OK`
- Expected body: the matching request object.

### 7. Request a nonexistent ID

- Method and URL: `GET http://localhost:3000/api/requests/not-a-real-id`
- Headers/body: none
- Expected status: `404 Not Found`
- Expected body: `{ "error": "Service request not found." }`

### 8. Replace a request with PUT

- Method and URL: `PUT http://localhost:3000/api/requests/{id}`
- Header: `Content-Type: application/json`
- Body:

```json
{
  "title": "Laptop needs an update",
  "description": "Install the latest approved operating system updates.",
  "requesterName": "Morgan Patel",
  "priority": "Low",
  "status": "In Progress"
}
```

- Expected status: `200 OK`
- Expected body: the updated object; its `id` and `createdAt` remain unchanged.
- To test PUT validation, omit `requesterName`; expect `400 Bad Request` with `{ "error": "'requesterName' is required." }`.
- To test a missing request, use an unknown ID with a valid body; expect `404 Not Found` with `{ "error": "Service request not found." }`.

### 9. Partially update a request with PATCH

- Method and URL: `PATCH http://localhost:3000/api/requests/{id}`
- Header: `Content-Type: application/json`
- Body: `{ "status": "Resolved" }`
- Expected status: `200 OK`
- Expected body: the full request object with status changed and other fields unchanged.
- To test PATCH validation, send `{ "status": "Waiting" }`; expect `400 Bad Request` with `{ "error": "'status' must be Open, In Progress, or Resolved." }`. Sending `{ "id": "new-id" }` must also return `400 Bad Request`.
- To test a missing request, use an unknown ID; expect `404 Not Found` with `{ "error": "Service request not found." }`.

### 10. Delete a request

- Method and URL: `DELETE http://localhost:3000/api/requests/{id}`
- Headers/body: none
- Expected status: `200 OK`
- Expected body: `{ "message": "Service request deleted successfully." }`
- Requesting the same ID afterward returns `404 Not Found`.
- Deleting an unknown ID also returns `404 Not Found` with `{ "error": "Service request not found." }`.

### 11. Access an unknown route

- Method and URL: `GET http://localhost:3000/unknown`
- Headers/body: none
- Expected status: `404 Not Found`
- Expected body: `{ "error": "Route not found: GET /unknown" }`

### 12. Send malformed JSON

- Method and URL: `POST http://localhost:3000/api/requests`
- Header: `Content-Type: application/json`
- Body (raw text, not valid JSON): `{ "title":`
- Expected status: `400 Bad Request`
- Expected body: `{ "error": "Request body contains invalid JSON." }`

## How the Files Work Together

Express first parses JSON in `server.js`, then matches the URL to a route in `requestRoutes.js`. The selected controller validates the request and works with the array exported by `data/requests.js`. If a URL or request fails, the not-found or error middleware returns a consistent JSON error. The server uses the port from `.env`, with `3000` as a fallback.

## Limitations and Future Improvements

Requests live only in the server's memory. They reset whenever the server restarts, and this storage is not suitable for multiple server instances or production data. A future version could use a database, add automated tests, add authentication and authorization, and deploy with environment-specific configuration. This learning API does not include authentication and should not be described as fully secure.

## Presentation Guide

- **Purpose:** Explain that the API tracks IT or facilities service requests using standard HTTP operations.
- **Node.js:** The JavaScript runtime that runs the server outside a browser.
- **Express.js:** A Node.js library that makes it easier to define routes and middleware.
- **REST API:** A way for clients to work with resources through URLs and HTTP methods.
- **Routes and controllers:** Routes match method/path combinations; controllers validate input and perform the requested operation.
- **HTTP methods:** GET reads, POST creates, PUT replaces editable details, PATCH changes selected fields, and DELETE removes a request.
- **JSON:** The format used for request bodies and API responses.
- **Middleware:** Functions that run during request handling; this project uses JSON parsing, 404 handling, and centralized error handling.
- **Status codes:** 200 means success, 201 means created, 400 means invalid input, and 404 means the resource or route was not found.
- **Postman demonstration:** Create a request, copy its returned ID, retrieve it, update its status, list requests, and delete it. Also demonstrate one validation error. Explain that restarting the server clears the in-memory data.
